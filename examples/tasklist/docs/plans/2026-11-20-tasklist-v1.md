# tasklist v1

Round out the `tasklist` CLI: a count command, repo hygiene, completing and removing tasks, and writes that stay correct when several processes run at once.

## How to run this plan

For the AO orchestrator:

- Spawn one worker per step. Pass the step's `Worker:` flags to `ao spawn` exactly as written, plus `--name "[<tier>] <step title>"` and a prompt that contains the step's full text and the path of this file.
- Start a step only after every step in its `Depends on` has merged. Steps with no unmerged dependencies may run in parallel.
- If a step has no `Worker:` line, use the standard tier below.
- Every step keeps `python3 -m unittest` passing and adds tests for what it changes.

## Worker tiers

| Tier | Worker flags |
|------|--------------|
| light | `--agent claude-code --model claude-sonnet-5-5 --effort medium` |
| standard | `--agent claude-code --model claude-opus-5-5 --effort medium` |
| deep | `--agent claude-code --model claude-opus-5-5 --effort high` |

## Step 1: `count` command

Add `tasklist count`, printing `<pending> pending / <total> total`.

- Files: `tasklist/cli.py`, new test in `tests/`
- Depends on: none
- Risk: low. Mirrors the existing `list` command.
- Tier: light
- Worker: `--agent claude-code --model claude-sonnet-5-5 --effort medium`

## Step 2: Repo hygiene

Add a `.gitignore` covering `tasks.json`, `__pycache__/` and `*.pyc`. Add a "Commands" section to `README.md` listing every command.

- Files: `.gitignore`, `README.md`
- Depends on: none
- Risk: low. No code changes.
- Tier: light
- Worker: `--agent claude-code --model claude-sonnet-5-5 --effort medium`

## Step 3: `done` and `rm` commands

Add `tasklist done <id>` (marks a task done) and `tasklist rm <id>` (deletes it). An unknown id prints an error to stderr and exits with status 1.

Task ids must never be reused, even after `rm`. The current `add` assigns `len(tasks) + 1`, which breaks this once a task is removed; fix it.

- Files: `tasklist/store.py`, `tasklist/cli.py`, tests
- Depends on: none
- Risk: medium. Changes id assignment for existing data files.
- Tier: standard
- Worker: `--agent claude-code --model claude-opus-5-5 --effort medium`

## Step 4: Safe concurrent writes

Running several `tasklist add` processes at the same time loses tasks, and a crash during `save` can leave a truncated `tasks.json` that no longer parses.

Make every read-modify-write in `store.py` safe across processes:

- Writes are atomic: write a temp file in the same directory, then `os.replace`.
- Read-modify-write is serialized with an exclusive file lock (`fcntl.flock` on a sidecar lock file). Windows support is not required.
- Add a test that starts 20 processes, each adding 10 tasks to the same file, and asserts 200 tasks with 200 unique ids.

- Files: `tasklist/store.py`, tests
- Depends on: 3 (both change `tasklist/store.py`)
- Risk: high. Concurrency and data-loss bugs; the test must not be flaky.
- Tier: deep
- Worker: `--agent claude-code --model claude-opus-5-5 --effort high`
